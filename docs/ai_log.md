# AI-журнал (Лабораторные работы №1–10)

В данном документе зафиксировано использование инструментов искусственного интеллекта при выполнении сквозного проекта «Система учёта заявок». Нейросети использовались как вспомогательный инструмент для генерации черновиков, анализа, поиска ошибок и ревью.

---

## Лабораторная работа №1. Анализ требований
*   **Задача:** Выделить роли, функциональные и нефункциональные требования, а также сущности предметной области.
*   **Модель:** DeepSeek V3
*   **Промпт:** *"Выступи в роли аналитика. На основе описания системы учёта заявок выдели 4 роли, 10 функциональных требований, 5 нефункциональных и 5 сущностей. Оформи в виде списков."*
*   **Результат ИИ:** Модель предложила базовую структуру, но допустила неточность в ролях (наделила Оператора правами Исполнителя).
*   **Проверка:** Я сверил результат с логикой работы техподдержки.
*   **Доработка:** Исправил права ролей вручную: убрал у Оператора возможность выполнять заявки. Добавил требование про экспорт в CSV.

## Лабораторная работа №3. Проектирование архитектуры
*   **Задача:** Предложить архитектурные варианты и провести ревью готовой диаграммы.
*   **Модель:** ChatGPT (GPT-4o)
*   **Промпт:** *"Предложи 2 варианта архитектуры для REST API на FastAPI (монолит и слоистая). Сравни их по тестируемости и простоте. Затем оцени мою диаграмму слоёв (прикрепил скриншот)."*
*   **Результат ИИ:** ИИ порекомендовал слоистую архитектуру (Controller-Service-Repository) и указал, что на моей диаграмме слой Database связан напрямую с Controller.
*   **Проверка:** Согласился с замечанием, так как это нарушает паттерн.
*   **Доработка:** Исправил стрелки на диаграмме в draw.io: Controller теперь идет только в Service, а Service — в Repository. Оставил выбранную слоистую архитектуру.

## Лабораторная работа №4. Интерфейс (UI/UX)
*   **Задача:** Сгенерировать макеты 5 экранов в едином стиле.
*   **Модель:** Яндекс Vibecraft.
*   **Промпт:** *[Был использован большой структурированный промпт с описанием 5 экранов, цветовой палитры и расположения элементов]*.
*   **Результат ИИ:** Vibecraft сгенерировал интерактивный прототип (React/Next.js), запросив перед этим подтверждение ТЗ.
*   **Проверка:** Проверил работу поиска, фильтров и модального окна удаления на сгенерированном прототипе.
*   **Доработка:** Сделал скриншоты экранов для отчета. Отклонил замечание ИИ по поводу мобильной версии (в ТЗ не требовалось).

## Лабораторная работа №5. База данных
*   **Задача:** Сгенерировать SQL-скрипты и сложные запросы JOIN.
*   **Модель:** DeepSeek V3
*   **Промпт:** *"Составь schema.sql для SQLite по моим сущностям (Users, Requests, Statuses и т.д.). Добавь ON DELETE CASCADE и CHECK. Напиши сложный JOIN для вывода статистики."*
*   **Результат ИИ:** ИИ выдал рабочий SQL, но забыл добавить поле `priority` в таблицу `Requests`, а в JOIN-запросе использовал неверный синтаксис для SQLite.
*   **Проверка:** Запустил скрипты в DB Browser for SQLite, получил ошибку.
*   **Доработка:** Самостоятельно добавил поле `priority` в `schema.sql` и `seed.sql`. Переписал JOIN-запрос, используя `LEFT JOIN`, чтобы выводились заявки без исполнителя.

## Лабораторные работы №6 и №7. Разработка API
*   **Задача:** Сгенерировать структуру роутеров и сервисов для FastAPI.
*   **Модель:** ChatGPT (GPT-4o)
*   **Промпт:** *"Напиши код для FastAPI (слои Controller, Service, Repository) для создания и получения заявок с использованием SQLAlchemy. Добавь валидацию Pydantic."*
*   **Результат ИИ:** Предложил хороший шаблон, но использовал старый синтаксис Pydantic v1 (`orm_mode = True`).
*   **Проверка:** При запуске FastAPI выдал ошибку `AttributeError`.
*   **Доработка:** Изменил синтаксис на Pydantic v2 (`from_attributes = True`). Также ИИ забыл добавить эндпоинты для справочников (`/users`, `/statuses`), я дописал их самостоятельно (`reference_router.py`).

## Лабораторная работа №8. Docker
*   **Задача:** Написать Dockerfile и docker-compose.
*   **Модель:** DeepSeek V3
*   **Промпт:** *"Напиши Dockerfile для проекта на FastAPI с базой SQLite и docker-compose."*
*   **Результат ИИ:** Дал стандартный Dockerfile, но не учел, что папка `venv` может скопироваться внутрь контейнера.
*   **Проверка:** При сборке контейнер весил слишком много.
*   **Доработка:** Создал файл `.dockerignore` и исключил `venv/`, `__pycache__/` и `.git/`. Убрал устаревшую строку `version` из `docker-compose.yml`.

## Лабораторные работы №9 и №10. Тестирование
*   **Задача:** Сгенерировать тест-кейсы и код автотестов на pytest.
*   **Модель:** DeepSeek V3
*   **Промпт:** *"Выступи в роли QA-инженера. Составь 20 тест-кейсов для CRUD API заявок (позитивные, негативные, граничные). Затем напиши код автотестов на pytest с использованием TestClient."*
*   **Результат ИИ:** ИИ предложил хорошие тест-кейсы, но в автотестах забыл, что pytest не видит папку `src` без конфигурации.
*   **Проверка:** Запустил тесты, получил ошибку `ModuleNotFoundError`.
*   **Доработка:** Создал файл `pytest.ini` с настройкой `pythonpath = .`. Также ИИ в тест-кейсах указал ожидаемый код 400 на ошибки валидации, я исправил на 422 (стандарт FastAPI).
